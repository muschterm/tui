## Residual risks worth knowing

- Partial staging B1 window: another process changing the same index entry
  between the final recheck and `update-index` is not detectable (ADR 0025).
- `git --no-optional-locks diff` can still refresh stat data under
  `index.lock` (ADR 0025 Known limits); content is never at risk.
- Worktree Git-discovery ceilings are process-wide and do not cover Git run
  by agents or terminals inside a worktree (ADR 0024).
- The worktree `running`/`failed`/`retryable`/Stop-following paths and the
  partial-staging re-pin logic are covered by unit tests only; the PTY
  harnesses exercise the fast paths.

### Plan (slices in order; orchestrate with implement → verify loops)

1. **Research first, in parallel with slice 2** (`implement-hard`, docs only):
   - Sublime Merge's actual interactive-rebase and commit-menu features from
     its official documentation (do not rely on memory): e.g. edit commit
     message, edit commit contents, squash/fixup with parent or selection,
     drop, move up/down, rebase onto, whatever else it offers. Produce the
     parity list with each item mapped to a `git rebase -i` todo form.
   - How to drive `git rebase -i` (Git 2.55) without an interactive editor:
     `GIT_SEQUENCE_EDITOR`/`sequence.editor` set to a server-owned helper that
     writes the pinned todo; `GIT_EDITOR` helper that supplies stored
     messages for reword/squash; how `edit` and `break` stop and resume;
     `--autosquash`, `--update-refs`, `--rebase-merges`, `exec`, signing,
     hooks (pre-rebase, post-rewrite), `rebase.*` config that must be
     neutralised; probes under `docs/research/go-feasibility-probes/`.
   - Output: `docs/research/go-interactive-rebase-2026-09-27.md` with a
     recommendation. **Ask the user** only about items that are risky or
     unclear — specifically `exec` lines (run arbitrary commands) and
     `--rebase-merges` — and about any parity item Sublime Merge has that the
     research cannot map safely. Everything else follows the parity list.
2. **Fetch & prune** (small; server + TUI + PTY):
   - `git.fetch` gains all-remotes scope and a prune flag (fetch every
     configured remote, non-interactive credentials as today). Report pruned

     `git fetch --porcelain` if the research confirms the Git version).
   - TUI: separate Fetch and Fetch & prune actions (keys, menu, toolbar),
     result notice listing removed refs.
   - `scripts/pty_git.py`: delete a branch in the local bare remote, run
     Fetch & prune, verify `origin/<branch>` is gone with `git`.
