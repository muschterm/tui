# Use complete snapshots and durable command receipts for the first Go slice

The initial Go reference uses versioned, authenticated loopback HTTP commands and WebSocket full-state snapshots, with each accepted command and its receipt committed alongside state in one SQLite transaction. A single serialized transition boundary makes snapshot subscription coherent and command retries deduplicable without introducing an event log and replay cursor before real provider workloads justify them; the cost is snapshot bandwidth, retained receipt growth and a deliberately bounded first implementation. Client view documents are stored separately by client identity, and server restart interrupts preserved fixture execution until explicit Resume; see [the concrete v1 contract and limits](../design/go-slice.md#application-protocol-v1).
