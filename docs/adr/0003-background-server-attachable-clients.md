# Keep application work in a background server

The application server owns running work and authoritative live state, while a TUI attaches, catches up, and may exit without stopping agents. The user selected explicit server start/status/stop commands and automatic startup when opening the TUI so a future web frontend can use the same boundary. Each language reference includes its own server and TUI, with one server per user/application and configured home; multiple clients connect through a shared authenticated loopback HTTP/WebSocket contract, with SSH forwarding for remote access. This adds lifecycle, synchronization, and recovery work; clients must reconcile accepted commands without repeating side effects. Executable names in examples are placeholders. See [server behavior](../design/server.md) and [storage](../design/storage.md) for persistence and recovery decisions.
