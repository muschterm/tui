# Preserve application state in a user-level home with SQLite

Each application keeps preserved state under its own directory in the user's home, overridable through an application-specific environment variable, with SQLite holding as much state as practical and auxiliary files where necessary. The application server is the authoritative writer; clients use its contract rather than opening the database. This makes threads, history, queues, drafts, and preferences independent of an individual checkout and keeps backup and recovery centered on one application home, at the cost of migration and artifact-consistency responsibilities. Example names such as `~/.myapp/` and `MYAPP_HOME` are illustrative, and separate native implementations need not share a SQL schema. See [storage and recovery](../design/storage.md).
