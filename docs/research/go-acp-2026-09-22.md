## Defects corrected during continuation

- **Dispatch races:** initialization/settings I/O left time for queue edits,
  removal, reordering or thread removal. Dispatch now rechecks the queue head
  identity/revision and lifecycle before sending. Stale setup failures do not
  poison replacement input. Tests cover these command interleavings.
- **Cancellation acknowledgment:** cancelling the local request context could
  complete the waiter before the adapter ended work. The prompt request now
  stays alive until the peer response or connection end; a bounded fallback
  ends an uncooperative adapter. Resume during a running/waiting turn is rejected,
  preserving live approval calls.
- **Shutdown:** manual probes join the shutdown wait, and Close after Kill
  still waits for process reaping. The earlier handoff's trailing-chunk,
  turn-scoped-note, inactive-Stop and startup-probe fixes were verified too.
- **Session/options:** dead connections are detected before reuse; the next
  dispatch can load the recorded session. Server and TUI use live option
  catalogues, including newly added fields, instead of stale probe mappings.
- **Fixture regression:** dynamic agent menus had removed the selectable Demo
  Reference model, blocking first Send. The fixture's existing model/effort
  choices are restored while the agent picker remains dynamic. Keyboard and
  PTY coverage exercise this path.
- **Presentation:** real-agent acceptance no longer says “Demo.”

The [checkpoint](../implementation/acp-checkpoint.md) and [ADR 0013](../adr/0013-server-owned-acp-agent-processes.md)
now distinguish Resume's dispatch gate from upstream session loading, and local
approval handoff from an upstream receipt acknowledgment. Typed-SDK decoding
claims were reconciled with the implementation tests.
