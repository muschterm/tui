## Findings and limits

- **Deln0r/ygo v1.20.1 computes the wrong local insert position after certain remote deletes.** It diverges from Yjs in 21 of 30 seeded histories and corrupts surrogate pairs in 12. Its replicas still converge with one another, which is why convergence-only fuzzing, and possibly its fixture suite, does not catch this. A four-operation reproduction is in `min_test.go`. It is disqualifying until fixed upstream. The bug has not been reported upstream; reporting it is a remote action left to the user.
- **Incremental updates are not Yjs-sized in either Go library.** reearth's `Doc.OnUpdate` encodes `encodeV1Locked(d, txn.beforeState)` ([doc.go](https://github.com/reearth/ygo/blob/v1.50.0/crdt/doc.go), `buildPhase2`), and Deln0r only offers SV diffs (`EncodeDiff`). Both embed the document's **entire delete set** in every update, so per-keystroke updates grow with deletion history: about 5 KB on average and 9.9 KB at the end, against 6 bytes in Yjs. Convergence is unaffected. The costs are bandwidth, append-log size and CPU (most of the per-op time above). Mitigations to evaluate: periodic compaction of the log into a full-state snapshot, batching keystrokes per transaction, or an upstream change to emit only the transaction's delete set. Deln0r's SV diff also re-sends a squashed item's already-known prefix (a 21-byte update for 6 new characters). It is idempotent but redundant.
- **Index units:** both libraries use UTF-16 code units, like Yjs, and neither rejects offsets that split a surrogate pair. The TUI should keep cursors on grapheme-cluster boundaries and convert only at the CRDT boundary. [`units.go`](go-feasibility-probes/collab/units.go) shows one approach with `rivo/uniseg` v0.4.7 (already in `apps/go`): per-cluster UTF-8 byte, UTF-16 and display-column starts, and a snap for remote offsets that land inside a cluster (for example between `e` and U+0301). Validating offsets at the server boundary is still required.
- **Undo is in-memory only.** The `UndoManager` stack does not survive a restart or reconnect in either library. The editor contract's cross-reconnect undo of a client's own edits needs an application design, such as a client-side manager on the client replica, stack reconstruction, or accepting loss on restart. The probe verified origin scoping only. Undo also depends on GC not freeing the content (reearth documents this).
- **Concurrency/API ergonomics:**
  - reearth takes the document lock inside `Transact`, its read methods and `ApplyUpdateV1`. Resolving root types through the `Doc` inside `Transact` deadlocks (its own docs, issue #138). Otherwise the API is closure-based, with `OnUpdate(update, origin)`, origin-typed transactions and context-aware variants.
  - Deln0r uses an explicit `WriteTxn`/`Commit`. Its read methods such as `Text.String` do not lock, so callers must hold `ReadTxn` (the probe does), and it has no per-transaction update event.
  - With either library, one server `Doc` per document plus one client replica per TUI fits the documented server design. Both ship websocket/persistence addons that the application would not need to adopt, because the core packages import nothing third-party.
- **reearth size/speed:** Go is roughly 20× slower per operation than Yjs in this shape, dominated by delete-set encoding. Decode and encode are faster than Yjs. It has not been profiled.
- **automerge-go:** not run (cgo/Rust toolchain and distribution cost). Upstream is inactive since 2024-10, has no tagged release and pins an older automerge-rs (#28). It is not wire-compatible with the Yjs ecosystem used by the Bun/Rust plans. These are notes only.

## Recommendation (for the user's decision)

Use **github.com/reearth/ygo** (pinned v1.50.0) as the Go collaborative-text library for the next slice:

- It matched Yjs 13.6.32 on every probe, including a 30-history differential.
- It is pure Go, MIT-licensed and actively maintained.
- It provides UTF-16 relative positions, origin-scoped undo, V1/V2 interoperability and SV-based sync.

Deln0r/ygo is not recommended at v1.20.1 because of the verified index divergence. automerge-go is not recommended because it is inactive and requires cgo.

Risks for reearth/ygo:

- Incremental update and log growth from full delete sets. Plan compaction, and consider an upstream issue.
- Per-op CPU cost at 1 MiB with long delete histories.
- Surrogate-splitting offsets are accepted, so the server must validate them.
- Undo is not durable.
- The lock-reentrancy footgun.
- It is a single-organisation project with a fast release cadence (78 versions), so pin it and re-run this probe on upgrade.

**Not verified here:** concurrent editing through a real server/websocket path; formatting and non-text types; GC/snapshot interaction with undo; memory at larger sizes or with many documents; Rust (yrs) interop; fuzzing beyond the seeds above; profiling; reearth's own CI claims.

## Reproduction

```sh
cd docs/research/go-feasibility-probes/collab
go vet ./... && gofmt -l .
go test -run TestWriteGoFixtures ./...            # writes testdata/go-*.{bin,txt,relpos,relidx}
go test -run TestDifferential ./...               # writes testdata/differential.json
S=$(mktemp -d); BUN_INSTALL_CACHE_DIR=$S/cache bun add --cwd $S --ignore-scripts --exact yjs@13.6.32
bun interop.mjs $S/node_modules testdata          # Go->Yjs checks, Yjs fixtures, differential adjudication
go test -race -count=1 -timeout 20m ./...         # everything, including the 1 MiB test (~3 min)
go test -short -race ./...                        # skips the 1 MiB test
```

Observed:

- `interop.mjs` printed `go(reearth) -> yjs: ... PASS`, `go(deln0r) -> yjs: ... PASS` and `differential vs yjs: 30 seeds; identical text reearth=30/30 deln0r=9/30`.
- `go test -race -count=1 ./...` passed.
- The Yjs 1 MiB reference numbers came from a scratch Bun script with the same edit shape; it is not committed.
