# Copy behavior follow-up — 2026-09-22

This records a focused repair to the Go reference client's copy paths. Source inspection and automated tests establish the routing and feedback behavior; they do not establish live clipboard delivery in a specific terminal, SSH client, or tmux configuration. No clipboard contents were read, and tests use an injected writer rather than the user's clipboard.

## Findings

| Boundary | Finding | Evidence |
| --- | --- | --- |
| Transcript and pointer selections | Both reached Bubble Tea `tea.SetClipboard`, which emits an OSC 52 request. Bubble Tea v2.0.9 documents that not all terminals support OSC 52, and its pinned `clipboard.go` has no acknowledgement path. The old transcript action reported success before the request was emitted. | Pinned local source: `$GOMODCACHE/charm.land/bubbletea/v2@v2.0.9/clipboard.go` and `tea.go`. |
| Prompt selection | Bubbles v2.2.1's textarea helper uses `github.com/atotto/clipboard`, so prompt copying used the local operating-system clipboard while transcript copying used OSC 52. Its internal failure message was not surfaced by the application status line. | Pinned local source: `$GOMODCACHE/charm.land/bubbles/v2@v2.2.1/textarea/textarea.go`; `CopySelection` and internal `copyErrMsg` handling. |
| Local OS clipboard | The same already-pinned clipboard package returns write errors. Its macOS implementation invokes `pbcopy`; Linux selects `wl-copy`, `xclip`, `xsel`, Termux, or Windows compatibility tools from those available. | Pinned local source: `$GOMODCACHE/github.com/atotto/clipboard@v0.1.4/clipboard_darwin.go` and `clipboard_unix.go`. |

## Behavior after the repair

Local TUI copies go through the OS clipboard helper and report completion only after it returns successfully. A real local write error is shown, followed by an OSC 52 fallback request whose acceptance is explicitly described as unconfirmed. SSH sessions use OSC 52 directly so the request can reach the user's outer terminal instead of writing to the remote host's clipboard. The visible transcript command and Ctrl+C / Ctrl+Shift+C selection commands share the same route. Mouse dragging still selects within the transcript/detail region; the selection can then be copied with Ctrl+C or Ctrl+Shift+C. Ctrl+C without a selection still detaches; Ctrl+Q always detaches. The keyboard-accessible F4 Commands menu retains “Copy visible transcript.”

This route uses the existing `atotto/clipboard` v0.1.4 module already brought in by Bubbles; no dependency version was added. The code never reads the clipboard. Automated tests inject a local writer and inspect the returned OSC 52 request without running the application output loop.

## Limits and verification status

The [2026-09-23 follow-up](../implementation/answer-status-copy-2026-09-23.md)
adds forwarded Command+C (Super+C) to the same selected-text route. A terminal
that consumes Command+C still requires its own native selection or the TUI's
Ctrl+C fallback; the application does not change terminal bindings.

Bubble Tea cannot confirm OSC 52 acceptance. SSH terminals and tmux may block, rewrite, or require configuration for clipboard escape sequences; failures in those paths can only be described as unconfirmed. Local Linux clipboard delivery depends on a supported clipboard utility and desktop session. Live macOS GUI, Linux desktop, SSH, and tmux clipboard checks remain **NOT RUN**. See [terminal capability research](terminal-capabilities.md#shortcuts-selection-and-clipboard) for the wider compatibility boundary.
