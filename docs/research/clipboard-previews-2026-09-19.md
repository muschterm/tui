# Clipboard context and attachment previews

Checked 2026-09-19 after the user's first CLI review. This is source inspection and a scoped implementation follow-up, **not a working clipboard/graphics integration**. No user clipboard contents were read or changed. Accepted presentation behavior is in [activity](../design/activity.md#clipboard-intake-and-read-only-previews). The user confirmed that ordinary text pastes into the prompt and images/copied files become attachments.

## Bounded implementation work

1. Establish server-owned artifact staging, bounded upload/read, durable publication and reference metadata. Preserve retries, per-thread drafts, immutable accepted captures and recovery. Avoid embedding image base64 in every snapshot/view document. Choose content/decoded-image limits and retention before accepting real bytes.
2. Add the centered read-only viewer with focus restoration, text selection/scrollbars, raw/rendered Markdown, eyeball preview control and expand/restore. Rendering text must not execute control sequences or fetch linked resources as a side effect.
3. Add explicit paste intake on the TUI client through verified terminal or local clipboard capabilities. An image-only terminal Paste may not deliver a usable input event; verify the actual gesture and provide an application-handled paste action where necessary. Do not poll the clipboard in the background. Native access on a remote machine does not read the desktop user's clipboard; test local-TUI/forwarded-server and remote-TUI topologies separately.
4. Add bounded asynchronous decoding/thumbnail caches and a negotiated image-placement lifecycle. Reuse transmitted data; remove only owned placements on preview close, resize, theme/layout changes, suspension and exit. Keep work off the input/render path and repeat the input-burst checks with large images.
5. Verify actual agent acceptance separately from local attachment/preview success. Do not silently convert or discard an unsupported image/file at dispatch. Failure preserves draft and attachments.

Test clipboard changes between Paste and Send, multiple representations of one item, copied files versus path-like plain text, image-only paste, unreadable/moved files, decode/size failures, navigation during intake, disconnect during publication, retry without duplicate attachments, queue/restart recovery, narrow viewer layouts and graphics-unavailable fallbacks. Exact format coverage and adapter selection remain implementation decisions; “copy anything” is not a claim of arbitrary-format preview or agent support.

This documentation update changes no executable behavior or dependency pins. Link targets, whitespace and consistency were checked; clipboard reads, image rendering and provider delivery were not tested.
