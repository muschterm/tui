# Image clipboard intake and kitty graphics for the Go TUI

Checked 2026-09-24 against the pinned Go module set (`charm.land/bubbletea/v2 v2.0.9`, `charm.land/lipgloss/v2 v2.0.6`, `github.com/charmbracelet/ultraviolet v0.0.0-20260811164956-006e29f97886`, `github.com/charmbracelet/x/ansi v0.11.8`, `github.com/rivo/uniseg v0.4.7`) on Linux/Wayland (Omarchy, Hyprland, `wl-clipboard 2.3.0`). This note extends [clipboard previews](clipboard-previews-2026-09-19.md) and the accepted behavior in [activity](../design/activity.md#clipboard-intake-and-read-only-previews). It is **research and scratch probing, not an implementation**. No application code changed. The proposed placement decision is [ADR 0018](../adr/0018-kitty-graphics-placeholders.md) (Proposed).

Kitty, Ghostty and WezTerm are **not installed** on this machine (`which` found only `foot` and `tmux`). No image was drawn in any terminal; every graphics statement below is source/document evidence or an off-screen buffer probe.

## Evidence

Evidence levels: **Probe** = ran here in a scratch program or command; **Source** = read the pinned module source; **Docs** = upstream documentation, not verified here; **NOT RUN** = deliberately not exercised.

### Clipboard intake

| Question | Finding | Evidence level |
| --- | --- | --- |
| Local tools | `wl-paste`/`wl-copy` (wl-clipboard 2.3.0) present; `xclip`, `xsel` absent. `WAYLAND_DISPLAY=wayland-1`. | Probe (`which`, `wl-paste --version`) |
| Listing offered types | `timeout 2 wl-paste --list-types` exits 0 and prints one MIME type per line. The current selection offered only `text/plain` variants; its contents were **not read**. Only type names matching image/file/text patterns were printed. | Probe |
| Reading a type | `wl-paste --no-newline --type image/png` (or `text/uri-list`) writes the raw representation to stdout. Exit status is nonzero when nothing is copied or the type is not offered. | Priority among representations | One copy often offers several: e.g. a browser image offers `image/png` and `text/html`; a file manager offers `text/uri-list` plus `text/plain` paths. Order: `text/uri-list`/`gnome-copied-files` (files) → `image/png`, then `image/jpeg`, `image/gif`, `image/webp` (decode support matters, see below) → `text/plain;charset=utf-8` → `text/plain`. Plain text that merely looks like a path stays text (activity spec). | Design inference |
| Probing with our own data | `wl-copy` would **replace the user's live clipboard** (and `--primary` the primary selection). Per the brief, write-then-read probes were **NOT RUN**. | Background polling | `wl-paste --watch` exists; the spec forbids clipboard polling. Read only on explicit Paste. | Docs; decision already accepted |
| macOS | `pbpaste` handles text only (it cannot emit PNG or file URLs). Images/files need AppKit `NSPasteboard` (`readObjects(forClasses:options:)` with `NSURL` + `NSPasteboardURLReadingFileURLsOnlyKey`, `NSImage`/`public.png`/`public.tiff`). `osascript -e 'the clipboard as «class PNGf»'` returns hex-encoded data in AppleScript record syntax — workable but awkward and slow; `osascript -l JavaScript` with ObjC bridge can write PNG to a temp file. Cgo/AppKit bindings would change packaging. | Docs ([NSPasteboard](https://developer.apple.com/documentation/appkit/nspasteboard/readobjects(forclasses:options:))); **NOT RUN** (no macOS host) |
| Remote gating | `internal/tui/clipboard.go:42` `terminalClipboardSession()` treats `HERDR_ENV=1` or any of `SSH_TTY`/`SSH_CONNECTION`/`SSH_CLIENT` as remote; `pasteClipboard()` (`:85`) then shows an unavailable notice. | Terminal typed clipboard (OSC 5522) | Kitty documents MIME-typed OSC 5522 read/write and a paste-event mode that offers types when the user pastes through the terminal; this is the only route that works across SSH. Not usable in this slice; keep as a future capability-gated path. | Docs ([kitty clipboard](https://sw.kovidgoyal.net/kitty/clipboard/)); Source (no parser); **NOT RUN** |

### Kitty graphics with the Bubble Tea v2 cell renderer

| Question | Finding | Evidence level |
| --- | --- | --- |
| Emitting APC outside the renderer | `tea.Raw(s)` produces `RawMsg`; the event loop calls `p.execute(fmt.Sprint(msg.Msg))` (`bubbletea/v2@v2.0.9/tea.go:866`), which appends to the same `p.outputBuf` the renderer flushes (`tea.go:1223`). The bytes are written verbatim and do not enter the cell buffer, so an APC **transmit** (`a=t`, no cursor movement) does not desynchronize the renderer's cell model. A direct placement (`a=p`/`a=T` without `U=1`) *does* draw at the real cursor position and the renderer does not know the pixels are there; its diffing may overwrite or leave stale cells. | Source; live terminal **NOT RUN** |
| Upstream helpers | `x/ansi/kitty` provides `Placeholder` (U+10EEEE), `Diacritic(i)` (row/column table), `Options` (incl. `VirtualPlacement`, chunking) and `EncodeGraphics`; `ansi.KittyGraphics(payload, opts...)` wraps the APC. No new dependency needed. | Source (`x/ansi@v0.11.8/kitty/graphics.go:105`, `writer.go:38`, `graphics.go:52`) |
| Placeholder width | Scratch program (`scratchpad/research/widthprobe`, same pinned versions via a separate module, no `apps/go` change): a row of 4 × (U+10EEEE + U+0305 + row/column diacritic) wrapped in `ESC[38;5;42m` measures **4** in `ansi.StringWidth`, `ansi.StringWidthWc`, `uniseg.StringWidth` and `lipgloss.Width`; a rounded-border box of it is 6; `ansi.Truncate(…,2)` gives 2. Drawing it into an `uv.ScreenBuffer` with both `GraphemeWidth` and `WcWidth` methods yields **4 cells, each width 1**, content `U+10EEEE̅̅`, foreground 42 preserved, and the rendered line re-emits the combining marks intact. | **Probe** |
| Image-id colour and profiles | The placeholder's foreground colour carries the image id (256-colour index or 24-bit RGB; a third diacritic carries the id's high byte). Bubble Tea downsamples styles to the detected colour profile; under ANSI-16 or `NO_COLOR` the id would be destroyed. Use ids 1–255 encoded as `38;5;N` only when the profile is ≥ ANSI256, and never enable graphics under `NO_COLOR`/ASCII profiles. Whether colorprofile preserves an exact 256 index through its conversion was only observed for the no-conversion path in the probe. | Probe (fg 42 preserved in buffer); Docs (kitty placeholder spec); profile conversion **NOT RUN** |
| Placeholder semantics | Transmit once with `a=t,f=100,i=ID,q=2` (chunked `m=1`, ≤4096 base64 bytes each), create a virtual placement `a=p,U=1,i=ID,c=COLS,r=ROWS,q=2`, then render placeholder cells in the view. The terminal scales the image to the placement box. Placeholders are ordinary text: they scroll, clip, move with layout and are cleared by the renderer like any cell, so resize and pane changes need no graphics bookkeeping beyond re-placing if `c`/`r` change. | Docs ([kitty graphics, Unicode placeholders](https://sw.kovidgoyal.net/kitty/graphics-protocol/#unicode-placeholders)) |
| Deleting owned images | `a=d,d=I,i=ID` deletes the image and frees its data (lowercase `d=i` keeps data). Emit for each owned id on viewer close/attachment removal (after the frame no longer contains its placeholders), and for all owned ids on exit and before suspend (`tea.Suspend`); re-transmit lazily after resume. Never use `d=A`/`a` (would delete other programs' images in a shared terminal). | Docs; **NOT RUN** |
| tmux | Placeholders pass through tmux as text, which is the main reason kitty designed them. The APC transmit/place/delete must be wrapped in DCS passthrough (`ESC P tmux; …` with doubled ESC) and needs `set -g allow-passthrough on`; replies to queries are not reliably routed back. Treat tmux as graphics-unavailable unless a query round-trip succeeds through it. foot and tmux were available but not exercised. | Docs (tmux(1) `allow-passthrough`); **NOT RUN** |
| Support query | Send `ESC_Gi=<id>,s=1,v=1,a=q,t=d,f=24;AAAA ESC\` followed by a DA1 request. A supporting terminal replies `ESC_Gi=<id>;OK ESC\` before the DA1 answer. ultraviolet's decoder returns such APC as `uv.UnknownApcEvent` (`ultraviolet/decoder.go:934`); Bubble Tea's `translateInputEvent` has no case for it and passes the value through unchanged (`bubbletea/v2@v2.0.9/input.go:52`), so `Update` receives it as `uv.UnknownApcEvent` and can parse `G…;OK`. DA1 is surfaced as `PrimaryDeviceAttributesEvent`, giving a deterministic "no reply" end without a sleep. | Source; live reply **NOT RUN** |
| Query gating | Mirror `terminal_colors.go:87` `supportsColorQueries`: only send the query after an actual XTVERSION reply names a known APC-safe parser (`kitty(`, `ghostty `; `WezTerm ` pending evidence), never from `TERM`/`TERM_PROGRAM`. Add a bounded timeout (e.g. 1 s) as a backstop to the DA1 terminator; silence means unavailable. Do not query under SSH-without-evidence differently: the query travels to the real terminal, so SSH is fine if the reply arrives; herdr/tmux are treated as unavailable unless the reply arrives. | Source (existing color gate); design inference |
| Cell pixel size | `CSI 16 t` → `CSI 6;h;w t`, decoded by ultraviolet as `uv.CellSizeEvent` (`ultraviolet/decoder.go:654`), passed through to `Update`. `CSI 14 t` → `uv.PixelSizeEvent` (window pixels; divide by cells). Bubble Tea's `WindowSizeMsg` carries no pixel size. Fallback when unanswered: assume a 1:2 cell aspect (width:height). | Source; live reply **NOT RUN** |
| Terminal support for placeholders | kitty ≥ 0.28 (placeholders introduced there). Ghostty documents kitty graphics support; Unicode placeholders are listed as supported in Ghostty's graphics implementation since 1.0 — re-verify on the installed build before claiming. WezTerm implements parts of the kitty protocol but placeholder (`U=1`) support is **unverified**; treat as unavailable until a query plus visual check passes. foot supports Sixel only, not kitty graphics. | Docs ([kitty changelog](https://sw.kovidgoyal.net/kitty/changelog/), [Ghostty features](https://ghostty.org/docs/features)); **NOT RUN** |

### Image handling with the standard library

| Question | Finding | Evidence level |
| --- | --- | --- |
| Decoding | `image/png`, `image/jpeg`, `image/gif` (first frame) via `image.Decode` with blank imports; WebP/HEIC/TIFF need `golang.org/x/image` or are unsupported. Unsupported formats remain file attachments with metadata and the fallback block, never a silent conversion. | Docs (Go stdlib) |
| Bounds | Call `image.DecodeConfig` first; reject > e.g. 16 MiB encoded or > 40 MP decoded before full decode (decompression bombs). Decode in a `tea.Cmd` goroutine with context cancellation; never in `View`. Cache one re-encoded PNG per attachment id and size class. | Design inference |
| Transmit format | Re-encode to PNG (`f=100`) so the terminal decodes; original PNGs can be sent unchanged after `DecodeConfig` validation. For thumbnails, downscale in Go (nearest/box filter, stdlib only) to ≤ cell box × cell pixels to bound transmit size; the full viewer can send the bounded original. | Docs (kitty `f=100`) |
| Aspect ratio | cols/rows from image pixels and cell pixels: `rows = ceil(h/ch)`, `cols = ceil(w/cw)`, then scale both down uniformly to fit the box; with the 1:2 fallback `cols ≈ 2·rows·w/h`. Kitty scales into the placement box without preserving aspect, so the box itself must carry the ratio. | Docs; design inference |

## Recommendation (summary)

1. **Intake (TUI client):** explicit Paste only. If `terminalClipboardSession()` is true or no native reader exists, keep today's notice/text path. Otherwise run `wl-paste --list-types` (2 s timeout) off the input path; choose files → image → text by the priority above. Text follows the existing `tea.PasteMsg`/text path. Files are sent to the server as path references for server-side capture at Send (like `@` mentions). Images are read with a size cap and uploaded to server staging as a draft artifact; the draft holds only the reference. Failures produce the existing non-blocking notice and never lose the draft.
2. **Graphics gate:** XTVERSION-gated `a=q` query with DA1 terminator and timeout; require colour profile ≥ ANSI256 and no `NO_COLOR`. Otherwise fallback.
3. **Placement:** Unicode placeholders with `U=1` virtual placements (ADR 0018). Transmit via `tea.Raw`; ids allocated from 1–255 per client, deleted with `d=I` on close/remove/exit/suspend.
4. **Surfaces:** viewer shows a fitted image inside its panel; draft attachment chips get a small thumbnail (e.g. 4×2 cells) only where the row height already allows it.
5. **Fallback:** a styled metadata block (type icon, name, pixel dimensions, byte size, format) filled with the panel's banded background, same geometry as the image box so layout never shifts when graphics become available.

## Limits and risks

- No live graphics run: kitty/Ghostty/WezTerm not installed; placeholder rendering, colour-id survival through colorprofile and deletion are unverified here.
- Clipboard reads of real image/file data **NOT RUN** to protect the user's clipboard; MIME ordering is based on documented conventions.
- `wl-paste` requires the compositor's data-control protocol for unfocused clients; behaviour under other compositors (GNOME lacks wlr-data-control) is unverified.
- Large transmits through `tea.Raw` share the output buffer with frames; a multi-MiB image can delay a frame. Chunk and bound thumbnails; send one image per command.
- Terminal multiplexers (tmux, herdr) and SSH: placeholders survive, transmits may not; replies may not return.
- The image id is the only cross-reference between text and pixels; another program in the same terminal using the same id collides. Randomise the id base per process within 1–255 and re-query on resume.
- macOS native intake requires AppKit access and a packaging decision (cgo vs `osascript`), not settled.
